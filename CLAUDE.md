## 1. Non-negotiable rules — copy this section verbatim into CLAUDE.md

1. **No fabrication.** Never invent numbers, results, datasets, model names, citations, quotes or claims about any paper. If something is unknown, write `TODO-VERIFY` and tell me.
2. **Every number is traceable.** Each number in the paper comes from a results file produced by a logged run (run_id, git commit, config, seed, timestamp). Tables and in-text numbers are generated by script into `paper/generated/` — never typed by hand.
3. **Test sets are touched last.** Prompts, thresholds, hyperparameters and module variants are chosen on dev/calibration data only. Test runs start only after `PROTOCOL.md` is frozen (its hash recorded in `COMPUTE_LEDGER.md`), and every test run is appended to `logs/test_runs.log`. If a bug forces a re-run, re-run every affected method and record why.
4. **Fair baselines.** Same backbone, quantization, retrieval access, top-k, generation limits and dev-tuning budget as RAG-Verify. Use the authors' code and prompts where available, record versions/commits, and record every adaptation. A baseline may be dropped only for a documented feasibility reason decided before its test results exist.
5. **Report everything.** Every method, dataset and metric in the frozen protocol appears in the paper, including where RAG-Verify loses or ties. No cherry-picked subsets, seeds, metrics or examples.
6. **Published numbers stay separate.** Numbers taken from other papers go in their own clearly labelled table, copied from the original paper with the table/figure number and setting differences recorded in `literature/reported_results.csv`. They are never presented as directly comparable to our runs.
7. **Verified citations only.** Cite a paper only after confirming online that it exists and that its metadata (title, authors, venue, year, DOI/arXiv ID) is right; log each check in `paper/refs_verification.csv`. Check every statement about what a paper does or finds against that paper's text. No "first to…" claims without a documented search.
8. **Claims match evidence.** Use "significant" only with a test result. Report effect sizes, 95% CIs and sample sizes. State limitations plainly.
9. **Honesty over agreement.** Give RAG-Verify the best fair chance to win, then report what the test results actually say. If the results don't support my hypothesis, tell me plainly — don't try to prove me right. If I ask for something that breaks these rules, say so and don't do it.
10. **Original, disclosed writing.** Write new prose; never copy sentences from papers or from my drafts/survey without rewriting and citing. Don't try to disguise AI-generated text or evade AI detectors. The manuscript gets an accurate AI-use statement describing how you were used. Figures are data plots, tables and code-drawn flow charts only — no AI-generated images or illustrations.
11. **72-hour hard stop** (§3). Check `COMPUTE_LEDGER.md` before launching any GPU job.
12. **My machine is not yours.** Work only inside this project folder. No system-setting changes, admin commands, or deleting anything outside the project. Never ask me to paste passwords or tokens into the chat; if a gated model needs a login, ask me to run the login command myself.
13. **Always resumable.** Keep `STATUS.md` current (done / running / next / blockers) and update it whenever a phase ends and before you stop. A fresh session must be able to resume from it alone.
